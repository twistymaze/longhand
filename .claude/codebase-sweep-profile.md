# Codebase sweep profile: Longhand

Project facts for the `codebase-sweep` skill. The skill's engine is generic; this file holds what is specific to Longhand. Finders and verifiers read it.

## The app

Longhand is a local-first desktop app for macOS and Windows: Tauri 2, a Rust workspace in `crates/`, the Tauri backend in `src-tauri/`, and a React interface in `src/`. It records an in-person session on one microphone (optionally with system audio), and makes a transcript and a summary. Code with `cfg(target_os = ...)` runs on one platform only; consider both platforms.

Important properties:

- A recording must never be lost. Data loss in record, save, move, and recovery paths is P0.
- One storage folder can be shared by several computers through a sync service. Two computers, and agents that use the `longhand-notes` skill in `plugins/longhand/`, can change the same files.
- The words that the code and docs use are defined in `CONCEPTS.md`. The interface says "note" where the code says "session".

## Decision sources

Before a finding is reported or confirmed, check these for intended behaviour:

## Threat model

The user chooses what leaves the computer, for example a summary service. A setting that the user chooses deliberately is not a security defect. A defect is a path where the app sends, exposes, or changes data without the user's choice. Untrusted inputs are: files in the storage folder (another computer or an agent can write them), downloads (models, updates), and model output (summaries, titles).

## Inventory

Run from the repository root:

```sh
git ls-files | grep -v '^reference-source/' | grep -E '\.(rs|ts|tsx|swift|cpp|py)$' > "$TMPDIR/sweep-files.txt"
```

Test code is:

- each file under a `tests/` folder, and `src/test/`;
- each `*.test.ts` and `*.test.tsx` file;
- in a Rust file, the lines from the first `#[cfg(test)]` to the end of the file (the test module is usually last in the file, so this count is close but not exact);
- the Python tests in `plugins/longhand/skills/longhand-notes/scripts/tests/`.

This `awk` counts app and test lines per top-level area:

```sh
awk 'FNR==1{t=0; f=FILENAME; s=(f ~ /(^|\/)tests?\//) || (f ~ /\.test\.tsx?$/)}
/^#\[cfg\(test\)\]/{t=1}
{split(f,p,"/"); k=p[1]"/"p[2]; if (s||t) T[k]++; else A[k]++}
END{for (k in A) print A[k]+0, T[k]+0, k}' $(cat "$TMPDIR/sweep-files.txt") < /dev/null | sort -rn
```

On 2026-10-15 the counts were about 94k lines of app code and 91k lines of test code.

## Borrowed code

Each folder with borrowed files has a `PROVENANCE.md`: one `## \`path\`` section per file, with `Repository`, `Revision`, `Source paths`, and `Status`. The status is `copied`, `modified — <what changed>`, or `reference` (written by us after reading upstream code; treat it as our code).

| Repository | Clone |
|---|---|
| https://github.com/fastrepl/anarlog | `reference-source/anarlog` |
| https://github.com/cjpais/Handy | `reference-source/Handy` |
| https://github.com/NVIDIA/NeMo-Speech.cpp | no clone; treat as `usage` |

The clones hold the recorded revisions. Get the upstream version of a file with:

```sh
git -C reference-source/<clone> show <Revision>:<Source path>
```

A new worktree has an empty `reference-source/`. Copy it from the main checkout before a sweep: `cp -cR <main checkout>/reference-source .`.

On 2026-10-15, borrowed app code was about 18.8k lines: 1.9k copied, 16.6k modified, 0.2k reference. Many modified files are now mostly our code (for example `src-tauri/src/lib.rs`); treat those as `own`.

## Dependencies for usage shards

Rust sources are in `~/.cargo/registry/src/index.crates.io-*/<crate>-<version>/`; get the version from `Cargo.lock`. JavaScript sources are in `node_modules/`. Candidates, in order of risk:

1. Audio input: `cpal`, `wasapi`, the macOS system audio code (`cidre`, `objc2`), `rtrb`, `rubato`, `hound`, `opus`/`ogg`.
2. Tauri and its plugins: `tauri`, `tauri-plugin-updater`, `tauri-plugin-store`, `tauri-plugin-single-instance`, `tauri-plugin-global-shortcut`, `tauri-plugin-window-state`, `tauri-nspanel`, `minisign-verify`.
3. Models: `ort`, `transcribe-cpp`, `ndarray`, `knf-rs`, `earshot`.
4. Files and storage: `notify`, `notify-debouncer-full`, `rusqlite`, `trash`, `tempfile` (when app code uses it).
5. Secrets and system: `keyring`, `security-framework`, `keepawake`, `sysinfo`.
6. Network: `reqwest`.
7. Editor: the `prosemirror-*` packages, `@handlewithcare/react-prosemirror`, `markdown-it`.
8. Async: `tokio`, `tokio-util`, `futures-util`.

## Risk areas

High risk (use `data-loss`, `concurrency`, and `error-recovery` where they fit):

- Capture and recording: `crates/recorder`, `crates/audio*`, `crates/aec`, `src-tauri/src/managers/capture.rs`, `src-tauri/src/managers/live.rs`.
- Saving and the library: `crates/session-save`, `crates/library`, `crates/session-core`, `src-tauri/src/managers/library.rs`, `destination.rs`, `audio_removal.rs`.
- Shared settings across computers: `crates/shared-settings`, `src-tauri/src/managers/shared.rs`, `settings.rs`.
- Processing and the summary queue: `crates/pipeline`, `crates/summarize`, `src-tauri/src/managers/processing.rs`.
- Updates: `src-tauri/src/managers/updates.rs`, `src-tauri/src/managers/updates/`.
- Secrets: `crates/secrets`, `src-tauri/src/managers/secrets.rs`.

## Candidate seams

Check each against the current code before you use it; add seams that you find.

1. **Record to saved note.** Start, record, stop, process, save into the storage folder: `managers/capture.rs` → `crates/recorder` → `crates/pipeline` → `crates/session-save` → `crates/library`.
2. **Crash during a recording.** Force quit or power loss while recording or processing, then the next start: recovery chunks in `crates/recorder`, `src-tauri/src/startup.rs`, the result flag in the note record file.
3. **Commands and the interface.** `src-tauri/src/commands/` ↔ `src/bindings.ts` ↔ the callers in `src/`: errors, events, and responses that arrive after the user moved on.
4. **Two computers on one storage folder.** In-use markers, a `pending` result flag, shared settings written by both, a note opened on one computer while the other saves it.
5. **Summary queue.** Request, model call, writing the summary, the interface update, a second regeneration, quit during a summary.
6. **Transcribe again.** Processing an existing note again from settings while it is open or while another job runs.
7. **Updates.** Check, download, verify, install, and the update notice.
8. **Agent edits.** The `longhand-notes` skill scripts in `plugins/longhand/` change notes and settings while the app reads, edits, or saves the same files.
9. **Settings change during a recording.** A change of microphone, system audio, model, or storage folder while a session records or processes.
10. **Editor and disk.** The note editor in `src/editor/` saves while the file on disk changes because of another computer or an agent.

## Tests

- Rust tests are in `#[cfg(test)]` modules at the end of each file and in `crates/*/tests/`. Hardware tests (`tests/hardware.rs`) and real-audio tests are opt-in and need `LONGHAND_*` variables; CI does not run them.
- TypeScript tests use `bun test` with happy-dom (`src/test/setup.ts`). Run them as `bun test ./src/`.
- `crates/audio-mock` is the fake audio device. Compare its behaviour with `cpal` for the `test-fidelity` lens.
- CI runs at UTC on macOS and Windows. A test that depends on the time zone can pass in CI and fail on a computer in another zone, or the reverse.
- `testdata/storage-folder/` is a checked-in storage folder that the real writers make; `crates/library/tests/test_storage_folder.rs` checks it.

## Lens models

Use the session model for all lenses except `test-fidelity` and `usage`, which can use `sonnet`.
